# 엣지 지표 (13주차)

`src/export_onnx.py`로 생성. 엣지 노드와 같은 조건(윈도우 1개씩, 1스레드)으로 측정. 노트북 CPU 기준.

## 1. ONNX 변환

| 항목 | pickle (rf.pkl) | ONNX (rf.onnx) | 목표 |
|---|---|---|---|
| 모델 크기 | 437 KB | **70 KB** | 500 KB 미만 |
| 윈도우당 추론 시간 (중앙값) | 1.32 ms | **0.018 ms** | 10 ms 미만 |
| 윈도우당 추론 시간 (95%) | 2.19 ms | 0.024 ms | |

- 정확도 확인: 윈도우 35,545개에서 두 모델의 동결 확률 차이 최대 1.6e-07 (ONNX는 float32 사용). 임계값 0.8 기준 판단 일치율 100.000%
- ONNX는 onnxruntime만 있으면 파이썬·scikit-learn 없이도 실행할 수 있어서, 실제 웨어러블(C/C++, 안드로이드)로 옮기기 쉽다

## 2. 윈도우 1개 처리 시간 (0.5초마다 1번)

| 단계 | 중앙값 (ms) | 95% (ms) |
|---|---|---|
| 특징 추출 (FFT, 10개) | 0.062 | 0.090 |
| 추론: pickle (scikit-learn) | 1.324 | 2.191 |
| 추론: ONNX (onnxruntime) | 0.018 | 0.024 |
| 합계: 특징 + ONNX 추론 | 0.080 | 0.114 |

- 측정: S01 데이터에서 2초 윈도우 1000개를 하나씩 처리
- 0.5초(500ms)마다 한 번 처리하므로 CPU를 거의 쓰지 않는다. 엣지 노드는 여기에 걸음 리듬 계산(10초 자기상관)이 추가됨
## 3. 실시간 엣지 노드에서 (MQTT, ONNX)

`src/edge_node.py` + `src/simulator.py --mqtt`, S01 1128~1150초 22초 재생.

| 항목 | 값 |
|---|---|
| 윈도우당 특징 추출 + 추론 | 0.6~1.3 ms (위 표보다 큰 이유: 0.5초마다 한 번만 실행해서 CPU 캐시가 식은 상태로 시작) |
| 센서 샘플 발행 → 엣지 판단 완료 (MQTT 포함) | 2~4 ms |
| 동결 확률 | pickle 모델일 때와 같음 (예: 1137초 0.82, 1144초 0.85) |
